# note-headless-fastpath

noteエディタへの自動投稿エンジン。AIエージェント（Hermes等）がCDP経由で**普段使いのChromeに接続**し、本文・画像の全挿入・保存・更新を自動で行う。

## 実測（2026-11-23）

| 工程 | 時間 |
|---|---|
| 全消去（更新時） | 2.3秒 |
| 本文77断片 | 66.3秒（0.86秒/断片） |
| 画像69枚（アップロード込み） | 101.4秒（1.47秒/枚） |
| 保存 | 0.03秒 |
| **合計** | **約2.8分**（手動作業の約15分から約6倍速） |

終了時文字数6,415（元記事6,157＋タイトル等と一致）・画像69/69枚で完全着地を確認。PCロック中でも動作する（CDP接続はOSロックと無関係）。

## 前提: 普段のChromeにデバッグ接続を許可する

1. Chromeで `chrome://inspect/#remote-debugging` を開く
2. 「このブラウザインスタンスのリモートデバッグを許可する」チェックボックスをON
3. 以後、外部ツールが接続を試みるたびに出る「リモート デバッグを許可しますか？」ダイアログで「許可する」を押す（接続試行ごとに出る・約20秒で自動的に消える）

> セキュリティ注意: 接続中はブラウザ内の全タブが操作対象になる。使わないときはチェックを戻す運用を推奨。

## なぜヘッドレスブラウザではダメか

noteは自動化ブラウザのログイン確立自体を拒否する（実測: クッキー注入7種全成功でも editor への遷移は必ずログイン画面へ302・UA＋Sec-CH-UA偽装でも不変・同じクッキーをurllibから送ると200）。拒絶はUA層より下で起きるため、UA偽装やクッキー移植に時間を溶かさないこと。

解決は「ログイン済みの普段のChromeをそのまま貸す」こと。Chrome 145以降の正規機能 `chrome://inspect/#remote-debugging` で許可を出すのが安全で確実。

## 使い方

```bash
BU_NAME=notetest BU_CDP_URL=http://127.0.0.1:9222 browser-harness < run_timing.py
```

- 接続は `BU_CDP_URL` 環境変数で明示する（9222はHTTP discoveryを一切返さないためcurlでの生死確認は無意味）
- attachできているかは `navigator.userAgent` で判定（`HeadlessChrome` が含まれるなら自前ブラウザへのフォールバック＝失敗）
- noteログインの判定は `editor.note.com/new` がリダイレクトされないこと（トップページの「ログイン」という文字列での判定は誤検出する）

## 実装の要点（落とし穴）

- **カバー（見出し画像）は新規下書きから作り直すと必ず消える**: 未設定のまま公開するとnoteアプリの一覧カードが灰色表示になり「画像が切れている」と誤認される。再構築後は必ずカバーを再設定する（エディタのタイトル上部アイコン→「画像をアップロード」→ファイルチューザ→クロップ保存。og:imageが production/uploads になれば設定済み）
- **貼り付けは「記事全体の1発貼り」が原則（2026-11-23実測）**: 単一 `<p>` 断片の貼り付けはエディタが既存段落にマージするようになり、断片連投では段落構造が崩れる。全断片を連結した1つのHTMLを**空エディタへ1回だけ貼る**と39ブロックが一瞬で構造化される（断片連投38秒 → 1発貼り2秒）。画像はメニュー経由では必ず本文末尾に入るため、配置は画像ブロックの切り貼り移動（Ctrl+X→目標段落クリック→Ctrl+V）で行う。画像の特定は `img.naturalHeight`、引用ブロックは `figure.blockquote` として描かれる点に注意


- **beforeunload**: noteエディタは保存済みでもハンドラが発火する。遷移前に `window.addEventListener('beforeunload', e => e.stopImmediatePropagation(), true)` をcapture段で注入。リロード確認ダイアログは `Page.handleJavaScriptDialog(accept=True)` でCDPだけで受諾できる（OSレベル操作不要）
- **画像挿入後のキャレット消失**: エディタは画像位置へ自動スクロールし、最後のテキスト要素がビューポート外（y≈-1600）に出る。以降のクリック・キー入力・貼り付けは黙って無効化される。→ `click_end_text()`（最終**テキストノード**の矩形＝行の中央を `scrollIntoView({block:'center', behavior:'instant'})` で画面内に戻してからCDP実マウスクリック→Ctrl+End→**フォーカスがProseMirrorに入ったことを検証**）を**毎ステップの貼り付け前に実行**。要素の上端をクリックするとキャレットが立たず全貼り付けが死ぬ
- **画像の挿入**: スラッシュメニューは無い。「メニューを開く」ボタン→「画像」→ `Page.setInterceptFileChooserDialog`（ナビゲーションのたびに打ち直す）→ `DOM.setFileInputFiles`。1枚1.1〜1.5秒（アップロード込み）。**テキストキャレットのままメニューを開くとチューザが死ぬ**ので、画像ステップの直前は body中央クリック＋Ctrl+End でキャレットを作り直す
- **画像は常に本文末尾に入る**: メニューからの画像挿入はキャレット位置を守らない（末尾に溜まる）。既存記事の途中に入れるには**画像ブロックの切り貼り移動**（画像クリック→Ctrl+X→目標段落を実クリック→Ctrl+V）が確実
- **公開ウィザード**: 最終ボタンは「投稿する」（新規）/「更新する」（既存記事）。**タイトル欄が空だとバリデーションで静かに止まる**（「押しても進まない」ように見える）。投稿する/更新するは js .click() では発火しない — CDP実マウスクリック＋直後の `Page.handleJavaScriptDialog(accept=True)` 連打ループで通す。成否は `curl https://note.com/supertask/n/<id>` のHTTPコードで確認
- **完了判定**: 文字数はProseMirror側の値を見る（`body.innerText` の「N 文字」は画像交じり長文で増えない実例あり）。画像は枚数照合
- **下書きID**: 数字ではない（`n76b488849626` 形式）。正規表現は `[a-z0-9]+`

## ファイル

- `note_flow.py` — エンジン本体（貼り付け・画像挿入・キャレット制御・検証関数）
- `run_timing.py` — 計測ランナー（新規パス＋全消去→再貼りの更新パスを1回で計測）
